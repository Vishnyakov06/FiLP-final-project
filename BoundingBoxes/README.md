# Задача B. "Bounding Boxes"

Ознакомиться с задачей подробнее можно на [Codeforces](https://codeforces.com/gym/106193/problem/B).

## Описание

Служба доставки предлагает несколько типов упаковочных коробок, каждая из которых является прямоугольным параллелепипедом. Неизвестно, какой тип коробки будет доступен в день отправки, поэтому коробка-сувенир должна помещаться в **каждую** из предложенных упаковочных коробок.

Сувенирная коробка тоже является прямоугольным параллелепипедом. При укладке её разрешается вращать, но стороны должны оставаться параллельны сторонам упаковочной коробки.

**Требуется найти максимальный возможный объём сувенирной коробки.**

### Входные данные

Первая строка содержит целое число `n` (1 ≤ n ≤ 1000) — количество типов упаковочных коробок.

Каждая из следующих `n` строк содержит три целых числа `w_i`, `h_i`, `d_i` — ширину, высоту и глубину i-й упаковочной коробки (1 ≤ w_i, h_i, d_i ≤ 1000).

### Выходные данные

Выведите наибольший возможный объём сувенирной коробки, которая помещается во все упаковочные коробки.

---

## Решение задачи

### Ключевое наблюдение

Если отсортировать стороны каждой упаковочной коробки по возрастанию — `a ≤ b ≤ c` — то сувенирную коробку со сторонами `x ≤ y ≤ z` можно всегда повернуть так, чтобы она влезла в упаковочную, если выполняется условие:

```
x ≤ a,  y ≤ b,  z ≤ c
```

Это верно, поскольку оптимально сопоставлять стороны по размеру: наименьшую к наименьшей, среднюю к средней, наибольшую к наибольшей. Такое сопоставление всегда достижимо вращением.

### Алгоритм

Нужно максимизировать объём `x × y × z` при ограничении: для **каждой** коробки выполняется `x ≤ a_i`, `y ≤ b_i`, `z ≤ c_i`.

Максимальные значения при таких ограничениях — просто минимумы по всем коробкам:

```
x = min(a_i),  y = min(b_i),  z = min(c_i)
```

где `a_i ≤ b_i ≤ c_i` — отсортированные стороны i-й коробки.

### Проверка на примере из условия

| Коробка | Исходные стороны | После сортировки |
|---------|-----------------|-----------------|
| 1       | 6 5 6           | 5, 6, 6         |
| 2       | 2 10 10         | 2, 10, 10       |
| 3       | 3 8 4           | 3, 4, 8         |

Минимумы: `min(5, 2, 3) = 2`, `min(6, 10, 4) = 4`, `min(6, 10, 8) = 6`

Объём: `2 × 4 × 6 = 48` ✓

## Описание решения на C#

[Программа](BbCSharp/Program.cs) считывает число упаковочных коробок `n`, затем для каждой коробки считывает три числа — её стороны.

Стороны каждой коробки сортируются по возрастанию с помощью `Array.Sort`, после чего обновляются три переменных: `minA`, `minB`, `minC` — минимумы наименьших, средних и наибольших сторон соответственно. Для обновления используется `Math.Min`.

После обхода всех коробок ответ вычисляется как произведение трёх найденных минимумов. Для предотвращения переполнения результат приводится к типу `long` перед умножением.

**Временная сложность:** O(n) — один проход по всем коробкам.

**Пространственная сложность:** O(1) — используется лишь несколько переменных.

## Описание решения на F#

[Программа](BbFSharp/Program.fs) считывает число упаковочных коробок `n`, затем для каждой коробки считывает три числа — её стороны.

Все коробки считываются и сортируются одновременно с помощью `Array.init` — для каждой строки стороны разбиваются, преобразуются в `int` и сортируются по возрастанию через `Array.sort`. В результате получается массив массивов вида `[| a; b; c |]`, где `a ≤ b ≤ c`.

Затем `Array.reduce` проходит по всем коробкам и накапливает поэлементные минимумы: наименьших сторон, средних и наибольших. Накопитель `acc` — это массив из трёх текущих минимумов, который обновляется на каждом шаге сравнением с очередной коробкой `d`.

После свёртки получается массив `[| minA; minB; minC |]`. Элементы переводятся в `int64` через `Array.map`, после чего перемножаются вторым `Array.reduce` с оператором `( * )`.

Весь алгоритм представляет собой единый пайплайн `|>` без переменных и циклов.

**Временная сложность:** O(n) — один проход по всем коробкам.

**Пространственная сложность:** O(n) — хранится массив всех считанных коробок.

## Описание решения на Prolog

[Программа](BbProlog/Bb.pro) считывает число упаковочных коробок `n`, затем для каждой коробки считывает три числа — её стороны.

Точка входа — предикат `main`, который запускает `run` через `catch(run, _, true)`. Обёртка в `catch` нужна для того, чтобы подавить ошибку конца файла, которую SWI-Prolog генерирует после завершения чтения входных данных. Ответ к этому моменту уже выведен, поэтому ошибка просто игнорируется.

Предикат `run` реализует основную логику: считывает `n`, запускает чтение коробок, сворачивает их в минимумы и выводит объём. Также в начале и конце `run` снимаются показания времени и памяти через `statistics(runtime, ...)` и `statistics(heapused, ...)` — разница между ними даёт время работы в секундах и потреблённую память в мегабайтах.

Предикат `read_boxes` рекурсивно считывает коробки по одной строке. Каждая строка читается через `read_line_to_string`, разбивается на части через `split_string`, преобразуется в числа через `maplist(number_string, ...)` и сортируется по возрастанию через `msort`. База рекурсии — `read_boxes(0, [])`: когда коробок не осталось, возвращается пустой список.

Предикат `reduce_mins` рекурсивно сворачивает список коробок в одну тройку поэлементных минимумов. На каждом шаге голова списка сравнивается с результатом рекурсивного вызова для хвоста через предикат `pairwise_min`. База рекурсии — список из одной коробки: она сама и есть минимум.

Предикат `pairwise_min` принимает две тройки и возвращает новую тройку, где каждый элемент — минимум соответствующих элементов входных троек с помощью встроенной функции `min`.

После свёртки получается тройка `[MinA, MinB, MinC]`, произведение элементов которой и является ответом.

**Временная сложность:** O(n) — один рекурсивный проход по всем коробкам.

**Пространственная сложность:** O(n) — хранится список всех считанных коробок.
