## Описание
Двоичные форматы часто используют компактные представления целых чисел. Рассмотрите возможность записи в файл 32-разрядного целого числа без знака: вы всегда должны сохранять 4 байта для его представления. Однако во многих реальных приложениях целые значения, как правило, малы. Запись этих небольших значений с использованием фиксированного 4-байтового представления приводит к получению файлов, которые в основном заполнены нулевыми байтами.
Чтобы сделать представление более компактным, мы вводим следующую схему кодирования. Каждое значение представляется в виде последовательности байтов $b_1,b_2,...,b_k$, где каждое значение $b_i$ является целым числом от 0 до 255 включительно. Старший бит каждого байта служит флагом продолжения, а младшие 7 битов содержат фактические данные. Если флаг продолжения равен 1, за ним следуют дополнительные байты; для последнего байта это значение равно 0. Это представление имеет большой порядок следования, что означает, что $b_1$ содержит наиболее значимые биты закодированного значения.
Например, вот как найти компактное представление числа $n=112025$. Сначала мы находим его двоичное представление: $112025=110110101100110012$
Затем мы разбиваем его на 7-битные фрагменты, при необходимости добавляя нули слева: $0000110 / 1101011 / 0011001$
Первые два фрагмента содержат следующий фрагмент, поэтому для соответствующих байтов их старший значащий бит равен 1. У последнего фрагмента нет следующего, поэтому его старший бит равен 0. Это дает нам:
$b_1=100001102=134$
$b_2=111010112=235$
$b_3=000110012=25$
Вам задано целое число $n$, и ваша задача $-$ найти его компактное представление.

#### Входные данные
Единственная строка содержит единственное целое число $n,(0\leqslant n \leqslant 231-1)$.

#### Выходные данные
Выведите последовательность целых чисел от 0 до 255 включительно, представляющую компактную кодировку $n$. Кодировка не должна содержать начальных байтов с нулевыми битами данных: то есть она не может начинаться со 128.

## Решение задачи
Для решения задачи необходимо преобразовать целое число $n$ в последовательность байтов по правилам компактного кодирования. Основная сложность заключается в правильном разбиении числа на 7-битные фрагменты и корректной расстановке флагов продолжения в формате big-endian (от старшего к младшему).
Поскольку итоговое представление должно быть в порядке от старших битов к младшим, алгоритм сначала извлекает группы по 7 бит, начиная с конца числа. После того как все значащие биты извлечены, полученные фрагменты объединяются в обратном порядке. Для каждого байта, кроме самого последнего в последовательности, устанавливается старший (8-й) бит в значение 1 (что соответствует добавлению 128), сигнализируя о наличии следующих байтов.
Минимальное количество байтов определяется количеством значащих бит числа. Особым случаем является $n = 0$, который всегда кодируется одним байтом со значением 0.

## Описание решения задачи на C$\#$
Программа на C# считывает входное число $n$ как тип `long`, чтобы избежать переполнения при обработке значений до $2^{31}-1$.
Сначала обрабатывается базовый случай: если $n$ равно 0, программа сразу выводит "0". Для остальных чисел создается список `bytes`, в который поочередно записываются результаты операции `n & 0x7F` (извлечение 7 младших бит). После каждого извлечения число сдвигается вправо на 7 бит (`n >>= 7`). Этот процесс продолжается, пока $n$ больше нуля.
Поскольку извлечение происходило от младших бит к старшим, список переворачивается с помощью метода `Reverse()`. Затем выполняется цикл по всем элементам, кроме последнего, где к каждому числу добавляется флаг продолжения через побитовое ИЛИ: `bytes[i] |= 128`. В завершение программа объединяет элементы списка в строку через пробел и выводит результат на экран.

## Описание решения задачи на F$\#$
Решение на F# реализует функциональный подход с использованием неизменяемых списков и рекурсии.
Основная логика разделена на два этапа. Первый этап $-$ рекурсивная функция `extractChunks`, которая отсекает по 7 бит от числа. Благодаря использованию оператора конструирования списка (`::`), новые фрагменты добавляются в начало списка. Поскольку рекурсия идет от младших бит к старшим, а добавление происходит в начало, итоговый список автоматически получается в правильном порядке big-endian без необходимости явного переворота.
Второй этап $-$ рекурсивная функция `setContinuationBits`. Она проходит по списку и с помощью сопоставления с образцом (`match`) определяет тип элемента. Если элемент последний в списке (паттерн `[last]`), он остается неизменным. Если за элементом следуют другие (паттерн `head :: tail`), к нему применяется побитовое ИЛИ с числом 128, и функция рекурсивно обрабатывает остаток. Результат работы преобразуется в строку и выводится в консоль.

## Описание решения задачи на Prolog
Решение в Prolog базируется на предикатах и рекурсивном обходе структуры данных.
Для преобразования числа используется предикат `extract_chunks`. Он работает рекурсивно: вычисляет остаток от деления на 128 (7 бит) и частное от деления (сдвиг). Чанки накапливаются в списке-аккумуляторе. Благодаря структуре головы и хвоста списка в Prolog, чанки, извлеченные последними (самые старшие), оказываются в начале итогового списка.
Предикат `set_continuation_bits` отвечает за расстановку флагов. Он использует два правила:
1. Базовый случай: если в списке остался только один элемент `[Last]`, он возвращается как есть.
2. Рекурсивный случай: если в списке более одного элемента `[H|T]`, то для головы `H` вычисляется значение с установленным старшим битом (`H \/ 128`), а хвост `T` обрабатывается следующим вызовом.

Программа считывает строку, преобразует её в число, пропускает через логические предикаты и выводит полученную последовательность, объединяя её пробелами.
