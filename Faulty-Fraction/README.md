# Задача. "Восстановление деления"

## Описание

Феликс изучал арифметику и вычислил результат деления положительного целого числа **a** на положительное целое число **b**. Результатом оказалось положительное целое число **c** (то есть **a** делится на **b** нацело). Феликс записал в тетрадь уравнение **a ÷ b = c** и вышел гулять.

Его младшая сестра Фиона решила пошутить: она взяла тетрадь и стёрла знак **÷**, в результате чего левая часть уравнения превратилась в единую строку цифр **s** (конкатенацию **a** и **b**).

Феликс вернулся и увидел в тетради **s = c**. Он забыл исходные значения **a** и **b** и теперь должен разбить строку **s** обратно на две части, чтобы восстановить уравнение деления.

**Требуется найти положительные целые числа a и b такие, что s является конкатенацией десятичных записей a и b, и выполняется a ÷ b = c.**

### Входные данные

Единственная строка содержит строку цифр `s` и целое число `c`. Оба значения состоят не менее чем из **1** и не более чем из **10⁵** цифр и не содержат ведущих нулей.

Гарантируется, что `s` является конкатенацией двух положительных целых чисел `a` и `b` (без ведущих нулей), таких что `a ÷ b = c`.

### Выходные данные

Вывести два положительных целых числа `a` и `b` без ведущих нулей такие, что `s` является конкатенацией `a` и `b` и `a ÷ b = c`. Если ответов несколько, вывести любой.

### Примеры

| Вход           | Выход      |
| -------------- | ---------- |
| 42 2           | 4 2        |
| 2025225 9      | 2025 225   |
| 239239239 1001 | 239239 239 |

---
## Решение задачи

### Ключевое наблюдение

Пусть строка `s` имеет длину **Ls**, а десятичная запись числа `c` — длину **Lc**. Нужно разбить `s` на префикс длины **La** (это `a`) и суффикс длины **Lb = Ls − La** (это `b`).

Из уравнения **a = b × c** следует, что длина `a` примерно равна длине `b` плюс длине `c`:

```
La ≈ Lb + Lc = (Ls - La) + Lc

2 * La ≈ Ls + Lc

La ≈ (Ls + Lc) / 2
```

Таким образом, позиция разбиения **La** может принимать лишь одно из трёх значений: `(Ls + Lc) / 2`, `(Ls + Lc) / 2 − 1` или `(Ls + Lc) / 2 + 1` (из-за целочисленного деления и возможных краевых случаев).
### Алгоритм

1. Вычислить оценку позиции разбиения: `La_est = (Ls + Lc) / 2`.
2. Перебрать три кандидата: `La_est − 1`, `La_est`, `La_est + 1`.
3. Для каждого кандидата **La**:
	- Проверить, что `0 < La < Ls`.
	- Извлечь `a = s[0..La−1]` и `b = s[La..Ls−1]`.
	- Проверить, что `b` не имеет ведущих нулей.
	- Проверить условие `a == b * c`.
4. Вернуть первый подходящий вариант.

Перебор ограничен тремя вариантами, поэтому алгоритм работает за **O(Ls + Lc)** — время, необходимое для одного умножения больших чисел.
### Проверка на примерах из условия

| Вход           | Ls  | Lc  | La_est | Проверяемые La | Ответ      |
| -------------- | --- | --- | ------ | -------------- | ---------- |
| 42 2           | 2   | 1   | 1      | 0, 1, 2        | 4 2        |
| 2025225 9      | 7   | 1   | 4      | 3, 4, 5        | 2025 225   |
| 239239239 1001 | 9   | 4   | 6      | 5, 6, 7        | 239239 239 |

## Описание решения на C\#

[Программа](Program.cs) считывает строку `s` и число `c`, а затем перебирает три кандидата для позиции разбиения **La**.

Позиция оценивается по формуле `(Ls + Lc) / 2`, после чего проверяются три значения: оценка, оценка минус 1 и оценка плюс 1. Для каждого кандидата строка делится на `aStr = s[0..La−1]` и `bStr = s[La..Ls−1]` с помощью `Substring`. Проверяется отсутствие ведущего нуля в `bStr`, затем оба фрагмента разбираются в `BigInteger` и проверяется условие `a == b * c`.

Первый подходящий вариант сохраняется в переменную `result` и выводится на экран.

**Временная сложность:** O(L) — три умножения больших чисел, каждое длиной не более L цифр.

**Пространственная сложность:** O(L) — хранятся строки и числа длиной до L цифр.

## Описание решения на F#

[Программа](Program.fs) реализует логику в виде двух чистых функций без изменяемого состояния.

Вспомогательная функция `check` принимает строку `s`, делитель `c` и кандидата **La**. Она возвращает `Some(результат)`, если разбиение корректно (нет ведущих нулей, выполняется `a = b * c`), или `None` в противном случае.

Функция `solve` формирует список из трёх кандидатов для **La**, применяет к ним `List.choose (check s c)` — что отбирает только успешные варианты — и берёт первый результат через `List.tryHead`. Если ни один вариант не подошёл, возвращается строка `"Не найдено"` через `Option.defaultValue`.

Весь алгоритм представляет собой единый пайплайн `|>` без явных циклов и мутаций.

**Временная сложность:** O(L) — три попытки, каждая требует одного умножения `BigInteger`.

**Пространственная сложность:** O(L) — список из трёх кандидатов и промежуточные `BigInteger`.

## Описание решения на Prolog

[Программа](program.pl) использует механизм бэктрекинга Prolog для перебора кандидатов.

Предикат `solve` разбирает входную строку, вычисляет оценку `La_Estimate = (Ls + Lc) // 2`, а затем с помощью дизъюнкции `(La = La_Estimate ; La is La_Estimate - 1 ; La is La_Estimate + 1)` порождает три кандидата для **La**. Prolog перебирает их автоматически при бэктрекинге.

Для каждого **La** предикат извлекает подстроки `A_Str` и `B_Str` через `sub_string`, проверяет отсутствие ведущего нуля в `B_Str` с помощью `\+ sub_string(B_Str, 0, 1, _, "0")`, затем преобразует оба фрагмента в числа через `number_string` и проверяет арифметическое условие `A is B * C`.

Предикат `run_test` запускает `solve` для каждого теста и выводит результат через `format`. Замеры времени и памяти производятся с помощью `statistics(runtime, ...)` и `statistics(memory, ...)`.

Предикат `test_all` перебирает список тестов через `member` и запускает `run_test` для каждого, используя `fail` для принудительного продолжения после каждого теста.

**Временная сложность:** O(L) — не более трёх вариантов, каждый требует одного умножения.

**Пространственная сложность:** O(L) — хранятся подстроки и числа длиной до L цифр.

### Тест-кейс 7: Большие числа, c = 1000000000

**Входные данные:**

```
10000000001 1000000000
```

**Ожидаемый результат:**

```
10000000000 1
```

Проверка: `10000000000 / 1 = 10000000000`... нет: `1 * 1000000000 = 1000000000` ≠ `10000000000`. Разбиение: `a = 10000000000`, `b = 1`, `a = b * c = 1 * 10000000000` — здесь `c` должно быть `10000000000`, но в условии `c = 1000000000`. Ищем другое разбиение: `a = 1000000000`, `b = 1`, `1000000000 = 1 * 1000000000` ✓ → строка `10000000001`, La = 10: `a = 1000000000`, `b = 1`.
